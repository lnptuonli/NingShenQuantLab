## 📊 关键技术点详解

### 1. 异步执行机制（@Async）

**为什么使用异步？**
- 数据获取可能耗时较长（几分钟到几小时）
- 不能阻塞主线程，影响其他请求
- 立即返回任务ID，客户端可以轮询查询状态

**实现方式：**

```java
// AsyncConfig.java - 配置线程池
@Configuration
@EnableAsync
public class AsyncConfig {
    @Bean(name = "quantTaskExecutor")
    public Executor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(5);        // 核心线程数
        executor.setMaxPoolSize(10);        // 最大线程数
        executor.setQueueCapacity(100);     // 队列容量
        executor.setThreadNamePrefix("quant-async-");
        executor.initialize();
        return executor;
    }
}

// LocalPythonExecutor.java - 异步方法
@Async("quantTaskExecutor")  // 指定使用 quantTaskExecutor 线程池
public CompletableFuture<ExecutionResult> executeAsync(String scriptName, List<String> args) {
    // 这段代码会在独立线程中执行，不阻塞主线程
    ExecutionResult result = doExecute(scriptName, args);
    return CompletableFuture.completedFuture(result);
}
```

**执行流程：**
1. Controller 调用 `executeAsync` 方法
2. Spring 立即返回一个 `CompletableFuture` 对象（占位符）
3. 实际执行在独立线程中进行（由线程池管理）
4. Controller 继续执行，不等待结果
5. 当 Python 脚本执行完成，触发 `thenAccept` 回调
6. 回调函数在独立线程中更新数据库

---

### 2. 任务状态管理

**任务生命周期：**

```
PENDING（待执行）
    ↓
RUNNING（执行中）
    ↓
SUCCESS（成功） / FAILED（失败） / CANCELLED（已取消） / TIMEOUT（超时）
```

**状态流转时机：**

| 状态 | 设置时机 | 位置 |
|------|----------|------|
| PENDING | 任务创建时 | DataServiceImpl#submitDataFetchTask |
| RUNNING | Python 进程启动时 | LocalPythonExecutor#executeAsync |
| SUCCESS | Python 进程退出码 = 0 | DataServiceImpl#updateTaskStatus |
| FAILED | Python 进程退出码 ≠ 0 | DataServiceImpl#updateTaskStatus |
| CANCELLED | 用户手动取消 | DataServiceImpl#cancelTask |
| TIMEOUT | 执行超时 | LocalPythonExecutor（超时检测） |

---

### 3. 日志收集机制

**两种日志来源：**

1. **系统日志（SYSTEM）**
   - 来源：Java 代码
   - 时机：任务提交、状态变更、错误处理
   - 示例：`"任务已提交，等待执行"`

2. **Python 日志（PYTHON）**
   - 来源：Python 脚本的 stdout/stderr
   - 时机：Python 执行完成后
   - 示例：`"成功获取 000001 数据 500条"`

**日志实时收集：**

```java
BufferedReader reader = new BufferedReader(
    new InputStreamReader(process.getInputStream(), StandardCharsets.UTF_8));

StringBuilder stdout = new StringBuilder();
String line;
while ((line = reader.readLine()) != null) {
    stdout.append(line).append("\n");
    log.info("[Python输出] {}", line);  // 实时打印到控制台
}
```

**日志存储策略：**
- 关键日志存入数据库（task_log 表）
- 完整日志可选存入文件（避免数据库过大）

---

### 4. 进程管理

**进程缓存（用于取消任务）：**

```java
// 缓存正在运行的进程
private final Map<Long, Process> runningProcesses = new ConcurrentHashMap<>();

// 启动时加入缓存
runningProcesses.put(taskId, process);

// 取消任务时终止进程
public void cancelTask(Long taskId) {
    Process process = runningProcesses.get(taskId);
    if (process != null && process.isAlive()) {
        process.destroy();  // 优雅关闭
        process.destroyForcibly();  // 强制关闭
    }
}
```

### 5. 数据库持久化

**任务记录（task_record）：**
- 记录任务元数据、状态、执行结果
- 支持查询、统计、监控

**任务日志（task_log）：**
- 记录详细执行日志
- 便于问题排查和审计

**事务管理：**
```java
@Transactional  // 确保任务记录和日志要么全部成功，要么全部回滚
public Long submitDataFetchTask(DataFetchRequest request) {
    // 插入任务记录
    taskRecordDao.insert(taskRecord);
    // 插入系统日志
    taskLogDao.insert(taskLog);
    // 如果任何一步失败，全部回滚
}
```

## 📈 性能和监控

### 并发能力
- **线程池配置**：核心5线程，最大10线程
- **队列容量**：100个任务
- **最大并发**：可同时执行10个数据获取任务

### 资源占用
- **内存**：每个任务约占用 10-50MB（取决于日志大小）
- **数据库连接**：每个任务占用1个连接（执行时）

### 监控指标
- 任务总数、成功率、失败率
- 平均执行时长、最长执行时长
- 当前运行中任务数

## 🐛 异常处理

| 异常类型 | 处理方式 | 返回给客户端 |
|---------|---------|-------------|
| 参数校验失败 | `@Valid` 自动校验 | 400 Bad Request |
| 日期范围不合法 | `IllegalArgumentException` | `{"code": 400, "message": "参数错误"}` |
| 任务不存在 | `IllegalArgumentException` | `{"code": 404, "message": "任务不存在"}` |
| Python 执行失败 | 捕获异常，更新任务状态为 FAILED | 任务状态为 FAILED，error_message 记录错误 |
| 进程超时 | `TimeoutException` | 任务状态为 TIMEOUT |
| 数据库异常 | `@Transactional` 回滚 | `{"code": 500, "message": "系统错误"}` |

## 🎓 总结

### 核心设计优势

1. **异步非阻塞**：立即返回任务ID，不阻塞主线程
2. **状态可追踪**：完整的任务生命周期管理
3. **日志可查询**：实时收集Python输出，便于排查问题
4. **进程可取消**：支持用户手动取消正在执行的任务
5. **事务一致性**：数据库操作有事务保证
6. **代码分层清晰**：Controller → Service → Executor → Python

### 可扩展性

- 新增其他数据获取类型（指数、基金等）只需修改 Python 参数
- 新增其他 Python 功能（特征计算、模型训练）复用相同架构
